    把 LLM 的全部工程细节压缩成一句话，它就是：一个把“给定前文，下一个 Token 最可能是什么”算到极致的函数。它不查库、不做关键词匹配、不检索现成答案——它在你把提示词递进去的那一瞬间，重新算了一遍整个语言的概率分布。

    ChatGPT 刚出现的那段时间，最常见的猜测是“它是不是把整个互联网存进去了”。三年过去，这个误解并没有消失，只是换了几种说法：有人担心模型“记住了”某段私有数据，有人奇怪它为什么不知道昨天发生的事，也有人把提示词写成搜索引擎查询语句，指望它像检索系统一样命中某一条记录。

    只要还停留在“存了 / 查了 / 匹配了”的直觉上，LLM 的很多行为就永远是玄学——幻觉是从哪来的？为什么同样的提示词两次回答不一样？为什么上下文一长它就开始忘事？为什么temperature调高之后它更容易胡说？

    这篇文章只解决一个问题：一堆矩阵乘法堆出来的函数，凭什么能理解自然语言，又凭什么能站在 Agent 的最中央当推理核心？我们沿着一条演进线往下走：先看语言模型最朴素的定义，以及它在 Transformer 之前究竟卡在哪里；再把“预测下一个 Token”这个目标函数拆开，看它是如何被逼着长出语言能力和世界知识的；然后下沉到 Token、架构、Attention、采样这四层工程细节；最后回到最初的问题，说清楚它为什么天然适合做 Agent 的大脑，以及它天生缺什么。

    01、从语言模型到大语言模型

    1.1 语言模型是什么

    Language Model（语言模型）的定义朴素得让人失望：给定一个 Token 序列，输出下一个 Token 的概率分布。

    形式化地写，模型要估计的是

    P(w_t | w_1, w_2, ..., w_{t-1})

    一旦这件事能做到，整句话的概率就可以按链式法则连乘出来：

    P(今天天气很好) = P(今天) × P(天气|今天) × P(很|今天天气) × P(好|今天天气很)

    所以“语言模型”这个词组里其实藏着两件事：它是一个打分器（判断一段文本有多“像人话”），也是一个生成器（按概率往外吐 Token）。LLM 只是把这两件事做到了前所未有的规模。

    1.2 演进：四个阶段，四次撞墙

    规则系统
   ↓
统计语言模型
   ↓
RNN / LSTM
   ↓
Transformer
   ↓
LLM

    规则系统（1960s - 1980s）。 早期 NLP 的思路是把语言学家的知识写成规则：主语 + 谓语 + 宾语构成句子，疑问句在末尾加问号。ELIZA 用模式匹配模拟心理治疗师，SHRDLU 在积木世界里能听懂指令，演示效果相当惊艳。但语言的长尾是无限的：每加一条规则就冒出一批例外，规则之间开始互相冲突，人工维护的成本随覆盖面指数上升。更致命的是，规则系统无法处理歧义，靠规则表难以在上下文里做出判断。

    统计语言模型（1990s）。 转向从数据里估计概率。最成功的形态是 N-gram：用马尔可夫假设砍掉历史，只看前 N-1 个 Token。

    P(w_t | w_1...w_{t-1}) ≈ P(w_t | w_{t-n+1}...w_{t-1})

    这个假设带来了两个无法绕开的代价。第一是数据稀疏：词表 5 万个词，四元组的理论空间是 5 万的 4 次方，也就是 6.25 × 10^18 种组合，再多语料也覆盖不了，绝大多数合法组合的计数都是 0；配合齐夫定律，出现次数为 0 和 1 的 n-gram 占了绝大多数。Kneser-Ney 平滑、回退、插值这些技术确实把估计做得更稳，但本质是在已知数据之间做插值，补不出真正没见过的新组合。第二是长距离依赖：n 从 3 加到 5，参数量的增长是灾难性的，而大部分语言现象的相关距离远超过 5 个词。

    神经网络语言模型与 RNN / LSTM（2003 - 2017）。 Bengio 等人在 2003 年用前馈网络加词向量预测下一个词，第一次让“词在向量空间里的距离代表语义相似度”成为可训练的结果，这也是 word2vec 一脉思想的源头。真正的接力棒交给了 RNN：把历史压进一个隐状态向量，一步步向前传，理论上能记住无限长的上下文。LSTM 用输入门、遗忘门、输出门缓解了梯度消失，在之后十年里成了序列建模的默认选择。

    但 RNN 系有两个结构性缺陷，且都无法靠调参解决。一是无法并行：第 t 步必须等第 t-1 步算完，序列维度彻底串行，GPU 的并行算力被浪费在等待上，训练规模被卡死在工程瓶颈里。二是信息瓶颈：整个历史必须压缩进一个固定维度的隐状态，序列越长，早期信息被稀释得越厉害；梯度消失虽被门控缓解却未被根治，实践中 LSTM 的有效上下文通常只有几十到几百个 Token。这就是为什么 Transformer 之前最好的翻译系统基本都在“句子级”工作，跨段落、跨文档的建模几乎无从谈起。

    Transformer 带来的变化（2017）。 Vaswani 等人在《Attention Is All You Need》里做了一个激进的选择：把循环结构整个删掉，只用注意力机制。这一步换来两个决定性的性质。

    • 任意两个位置之间的信息传递路径长度从 O(n) 降到 O(1)。 在 RNN 里，第 1 个词的信息要传到第 100 个词，得走 99 步；在 Self-Attention 里一步到位。长距离依赖不再是需要“对抗”的困难，而是默认能力。
    • 整个前向传播可以写成大型矩阵乘法，序列维度天然并行。 同一个 batch 里所有位置同时计算，训练吞吐比对 RNN 高出若干个数量级。

    第二条往往被低估。它意味着“模型能训多大”这件事，第一次从算法约束里被解放出来，转而变成一个纯粹的算力与数据问题——而这正是 Scaling Law 能够成立的前提。

    1.3 为什么是 Transformer 成了 LLM 的基础架构

    如果只看“效果好”，历史上不乏效果好的架构。Transformer 之所以成为几乎唯一的底座，是因为它同时在四个维度上没有明显短板：

    维度 说明
    可并行 训练时序列维度完全并行，能把上万张卡喂饱
    可扩展 加深加宽都是同一套结构，模型规模可平滑放大
    通用 只要能编码成序列，文本、代码、图像 patch、音频都能吃
    长程 位置间路径为 O(1)，长依赖建模是默认能力

    再加上 2020 年的 Scaling Law 与 2022 年 Chinchilla 的修正——在给定算力下参数量与训练数据量应当同比扩张（约每个参数配 20 个 Token），业界第一次拿到了“投入多少算力能换回多少性能”的粗略地图，于是资本和工程资源全部押注到同一条技术路线上：把 Transformer 堆大、把数据喂多。

    关于“涌现能力”，这里需要做一点纠偏。早期研究观察到某些能力在小模型上接近随机水平，规模跨过某个阈值后突然跃升，于是“能力涌现”被广泛引用。但后续研究指出，这种“突然”很可能部分来自评测指标的离散性——用连续指标（如 Token 级编辑距离）衡量时，同样的能力曲线是平滑上升的。工程上的含义很实际：不要指望某个参数规模是一道门槛，能力是渐变的；也不要因为“小模型也能做”就放弃规模带来的可靠性提升。 这两件事同时成立。

    02、LLM 的核心思想：预测下一个 Token

    2.1 训练目标只有一句话

    LLM 的全部训练信号来自一件事：

    给定前面的 Token
预测下一个 Token

    输入：

    今天天气很

    模型输出的不是一个词，而是整个词表上的概率分布，比如：

    好      0.42
不错    0.15
热      0.09
冷      0.04
...     ...

    训练时我们手里有真实的下一句，把它的概率取负对数当做损失，用梯度下降压低它。这就是交叉熵损失，也是最大似然估计：

    Loss = -log P(真实的下一个 Token | 前面的 Token)

    整段训练语料上把这个损失平均一遍，就是困惑度（Perplexity）。降低困惑度，就是模型训练的全部目标。

    2.2 为什么这个目标有效

    这里有个容易被跳过的关键：要压低困惑度，模型必须学会的东西远远不止语法。

    要猜到“小明把苹果放在桌子上，然后他吃了它”后面的 Token，模型得知道苹果是能吃的、桌子不是、“他”指小明。要猜对一段 Python 代码的下一行，它得理解缩进、变量作用域和常见 API。要猜对“法国的首都是____”，它必须真的把这条事实编码进参数。语言是人类知识最完整的投影载体，因此“预测下一个 Token”这个看起来极度狭隘的目标，实际上等价于一个覆盖所有知识的超大规模多任务学习。

    GPT-3 论文给出的解释是 meta-learning：模型在大规模文本上学会的不是某个具体任务，而是“如何从上下文中识别出当前要做哪件事”，然后即时执行。这一点是后面 Agent 能成立的根本前提。

    2.3 它不是数据库，也不是答案查询接口

    必须把三件事分开：

    • 它不是数据库。 数据库有精确的键值映射、可以枚举、可以 UPDATE、可以 DELETE、可以审计。LLM 的知识分布式地散布在数十亿参数里，以概率的形式存在。没有任何一个参数字段对应“法国的首都是巴黎”这句话。想改掉一条事实，需要动一片参数——知识编辑技术（ROME、MEMIT）在小范围上能做，但脆弱且容易产生副作用。
    • 它不是直接查答案。 一次前向传播就是一次概率分布的计算，答案是从分布里采样出来的。同一个问题问两次得到不同答案，不是 bug，是模型的正常行为。
    • 它是一个概率模型。 它学的是“什么最像人话”，而不是“什么是真的”。

    第三条的推论非常重要：幻觉是目标函数的直接产物，不是意外。 流畅性和真实性在统计上是高度相关但绝不重合的两件事。当上下文里的证据不足时，模型倾向于给出一个“语言上最自然”的续写——这正是编造一个具体数字、一个人名、一条论文引用时的内部机制。要减少幻觉，只能从外部补上约束（检索、工具、校验），而不能指望模型自己“更努力地想清楚”。

    2.4 一个容易被忽略的推论：思考必须发生在 Token 流里

    因为预测下一个 Token 是模型的唯一输出形式，模型能做的“计算量”就和它生成的 Token 数成正比。每生成一个 Token，就是一次完整的前向传播，就是一轮额外的计算。

    这个约束解释了两件事。第一，为什么 Chain-of-Thought 有效：把推理步骤显式写进 Token 流，模型就能用更多的 Token 换取更多的计算，从而处理单步无法完成的问题。第二，为什么近两年的方向是“测试时计算”（test-time compute）：既然计算可以靠生成换，那么让模型多想一会儿——无论是长链推理还是并行采样再投票——就能继续提升准确率，而不必再训练一个更大的模型。

    03、Token：模型理解世界的基本单位

    3.1 什么是 Token

    LLM 看不到字符，也看不到单词，它看到的是 Token——一串介于字符和词之间的子词单元。文本进入模型之前，会先被分词器（Tokenizer）切成 Token，再映射成整数 ID。

    一个常见的切分直觉大致是这样（具体结果取决于分词器实现）：

    "tokenization"        → ["token", "ization"]
"今天天气很好"         → ["今天", "天气", "很", "好"]
"unbelievable"        → ["un", "believ", "able"]

    3.2 Tokenization 是怎么做的

    主流算法是 BPE（Byte-Pair Encoding）：

    1. 把训练语料拆成最小单元（通常退回字节或字符）；
    2. 统计所有相邻单元对的出现频率；
    3. 把最高频的那一对合并成一个新单元；
    4. 重复第 2、3 步，直到词表达到目标大小（常见为 3 万到 20 万之间）。

    原始语料里出现越频繁的字符串，就越早被合并，最终成为独立 Token；罕见字符串则保留为多个子 Token 的组合。WordPiece 与 SentencePiece / Unigram 是同一思路的不同实现，前者偏语言模型似然，后者直接在原始文本上工作、不需要预分词，因此在多语言和中文场景中更常见。

    3.3 为什么不按字或词处理

    方案 词表规模 序列长度 主要问题
    按字符 / 字节 很小（百到千级） 极长 序列长度爆炸，注意力成本 O(n²) 直接吃掉收益；单字符信息量太低
    按词 极大（数十万起） 短 词表爆炸；新词、拼写错误、专有名词全部变成 OOV 无法表示
    子词（BPE 等） 可控（万到十万级） 适中 折中方案，无 OOV，序列长度可控

    子词方案同时解决了两个死结：没有 OOV（任何字符串都能退化成字节序列表示），常见词不浪费序列长度（高频词一个 Token 搞定）。这是工程上少有的双赢选择。

    3.4 Token 如何影响 Agent 的工程决策

    Token 不是一个语言学概念，它是 Agent 系统里最重要的计价单位和容量单位。

    • Context Window（上下文窗口）。窗口以 Token 计数。它要同时装下：系统提示词、工具定义（一个稍复杂的 Agent 常带十几个工具，光 schema 就能吃掉几千 Token）、历史对话、检索到的文档片段、以及当前这一轮的所有输出。窗口不是“可用空间”，而是“总预算”。
    • Token Cost（成本）。输入和输出分开计价，且输出单价通常更高。真正能省钱的杠杆是缓存：把系统提示词、工具定义、固定示例放在最前面并保持逐字节稳定，命中 Prompt Cache 后这部分成本可以下降一个数量级。所以提示词的结构稳定性直接等于钱——把时间戳、随机 ID 插到前缀里，就是把缓存命中率打掉。
    • Prompt 长度。长上下文不是免费午餐。研究已经表明，关键信息落在长上下文的中间位置时，模型的召回率明显低于首尾两端（这就是所谓的 lost in the middle）。所以“把所有资料都塞进去”通常不如“精准召回最相关的几段”。
    • RAG Chunk 大小。切片必须以 Token 为单位计算，而不是字符。chunk 太小，语义不完整，检索出来的片段模型没法用；chunk 太大，单次塞进窗口的噪声变多、成本上升、关键信息更容易被冲淡。实践中 300 到 800 Token 是常见起点，但真正决定效果的是切片是否沿着语义边界（标题、段落、代码块）切，而不是切在句子中间。

    还有一个更隐蔽的影响：Token 边界会改变模型的能力上限。 因为模型看到的是 Token 而不是字符，涉及字符级操作的任务——数字数、拼写、字符统计、精确对齐——它天然没有可靠的表征。数字尤其典型：如果把“1234”切成“12”和“34”，模型就无法逐位对齐做算术。这不是模型“笨”，而是输入表示的物理限制。

    04、Transformer 架构概览

    这一节不推数学，只建立结构直觉。一次前向传播的完整链路是：

    Input Tokens
      ↓
Embedding
      ↓
Transformer Blocks  × N
      ↓
Output Probability
      ↓
Next Token

    4.1 Embedding：把 ID 变成向量

    Embedding 是一张查表：Token ID → 固定维度向量（d_model，常见 4096、8192）。这张表在训练中一起学，学完之后语义相近的 Token 在向量空间里靠得近。

    注意一个前提：注意力机制本身对顺序完全无感。“小明打小红”和“小红打小明”在纯注意力眼里是同一堆向量的两种排列，如果不额外注入位置信息，两者无法区分。所以必须加位置编码：从最初的正弦函数编码，到可学习的位置嵌入，再到如今主流的 RoPE（旋转位置编码）——后者把位置信息直接编进 Query 和 Key 的相对关系里，对长序列外推更友好。

    4.2 Transformer Block：重复 N 层

    现代 LLM 由 N 个结构几乎相同的 Block 堆叠而成（7B 级别模型通常 32 层，百 B 级别可达 96 层以上）。每个 Block 里有两块真正做计算的子层：

    Self-Attention（自注意力）。 负责在 Token 之间搬运信息——用“检索 + 加权汇总”的方式，把相关位置的内容拉过来。

    Feed Forward Network（前馈网络）。 两层线性变换夹一个非线性激活，中间维度通常是 d_model 的 3 到 4 倍（4096 → 16384 这个量级）。激活函数从 ReLU 演进到 GELU，再到今天更常见的 SwiGLU。它的作用是在每个位置上单独做一次非线性变换，可以粗糙地理解为“加工和存储”：大量研究表明，事实性知识主要存储在 FFN 的参数里，注意力更像路由器。

    一个容易被忽略的账：以 7B 模型为例，FFN 占据了约三分之二的参数量，注意力只占三分之一左右。所以“模型的知识量”主要由 FFN 的规模决定，而“模型的结构化能力”更多取决于注意力的头数与维度。

    4.3 两个辅助结构，以及它们为什么重要

    Residual Connection（残差连接）。 每个子层的输出都写成 x + Sublayer(x)。这不是装饰：它让梯度有一条直通底层的高速公路，是几十层网络能够被训练起来的前提。换个角度理解，它让每一层只负责“对当前表示做增量修改”，而不是从头重建。

    Layer Normalization（归一化）。 稳定每一层的激活分布，防止数值在深层传播中漂移。现代模型大多改用 RMSNorm（去掉均值中心化，只做缩放），计算更省、效果相当；位置也从早期的 Post-Norm 全面转向 Pre-Norm，因为后者在深层模型上训练更稳定。

    4.4 输出层：从向量到概率

    最后一层的隐藏状态经过一个反嵌入矩阵（通常与 Embedding 权重共享）投影回词表维度，得到 logits——一个长度等于词表大小的原始分数向量，再经过 Softmax 归一化成概率分布。

    值得强调的一点是：整个前向传播里几乎没有任何分支或条件判断，只有矩阵乘法加非线性。 没有 if-else，没有循环，没有查表。这正是它能被 GPU 极度高效地并行执行、能被无限堆叠的物理原因。工程上的一切优化——并行训练、量化、蒸馏、KV Cache、FlashAttention——都是在这样一个规整的计算图上做文章。

    顺带一提近年的结构演进方向：MoE（混合专家）把单个 FFN 换成多个专家加一个路由，让总参数量可以远超单次激活的参数量；MQA / GQA 让多个注意力头共享 Key 和 Value，大幅压缩推理时的显存占用。它们改变的是效率，不是基本骨架。

    05、Attention：上下文的检索机制

    5.1 问题出在哪

    来看一个经典例子：

    小明把苹果放在桌子上，
然后他吃了它。

    要正确理解“它”，模型必须把“它”和“苹果”关联起来，而不是和“桌子”关联。RNN 处理这句话的方式是把整句压进一个隐状态，距离一远，早期信息就衰减了。

    Attention 的思路完全不同：不要压缩，让每个位置直接去看所有位置，按相关性决定看多少。

    5.2 Query、Key、Value 的直觉

    用图书馆检索来打比方：

    • Query（查询）：我想找什么。当前 Token 发出的问题。
    • Key（索引）：每个位置挂着的标签，用来判断“这里的内容和我相关吗”。
    • Value（内容）：每个位置真正携带的信息。

    计算过程是三步：

    1. 当前 Token 的 Query 与所有位置的 Key 做点积，得到相似度分数；
    2. 分数经过缩放和 Softmax，变成一组权重（和为 1）；
    3. 用这组权重对所有位置的 Value 做加权求和，得到当前 Token 的新表示。

    写成公式就是：

    Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V

    这里的 √d_k 不是随手加的。点积的方差随维度 d_k 线性增长，维度一大，分数就会变得极端，Softmax 会被推向饱和——几乎全部权重集中到一个位置，其余位置梯度接近 0，模型学不动。除以 √d_k 把分数拉回合适的范围，这是注意力能在大维度下正常工作的前提。

    5.3 回到那个例子

    当模型算到“它”这个位置的注意力权重时，“苹果”的 Key 和“它”的 Query 相似度最高，于是“苹果”的 Value 被大量取回，“它”的表示里就被注入了苹果的语义。这种关联完全不需要语法规则，也不需要人工标注——它是从“预测下一个 Token”的训练里自己长出来的。 模型之所以学会指代消解，是因为不学会它，困惑度就降不下来。

    5.4 Multi-Head Attention：为什么需要多个头

    一个注意力头只能学到一种相关性模式。但语言里的关系是多维度的：语法依存、指代、位置邻近、时态一致、实体共指……

    Multi-Head 的做法是把 d_model 切成 h 份（例如 4096 切成 32 个 128 维的头），每个头用自己独立的 Q/K/V 投影做一次完整的注意力计算，最后把所有头的输出拼接起来再线性投影回去。

    结果是模型获得了 h 个并行的、独立的视角，可以同时追踪多种关系。可解释性研究已经在真实模型里找到了职责明确的注意力头：有的专门盯前一个 Token，有的负责识别重复模式并补全（induction head），而这些头两两组合起来，就构成了 In-context Learning 的机械基础之一——模型在上下文里看到一组“A 对应 B”的示例后能照葫芦画瓢，本质上是靠这套复制回路实现的。

    5.5 因果掩码：为什么它是自回归的

    生成式 LLM 不能“偷看”未来。所以在计算注意力时，位置 t 只允许关注位置 ≤ t，未来位置被上三角掩码置为负无穷，Softmax 之后权重归零。这个 Causal Mask 是 GPT 类和 BERT 类模型的分水岭：加了它，模型只能从左往右看，适合生成；不加它，模型双向可见，适合理解类任务。

    5.6 代价与优化

    注意力最大的代价是复杂度：序列长度 n 时，注意力矩阵是 n × n，时间和显存都是 O(n²)。这就是上下文窗口不可能无限的硬约束，也是长上下文优化持续成为热点的原因。

    FlashAttention 是这一类优化的代表。它不改变 O(n²) 的复杂度，而是改变计算在 GPU 上的访存方式：通过分块计算和在线 Softmax，避免把完整的 n × n 矩阵写回显存，把注意力从“显存带宽瓶颈”变成“接近算力瓶颈”，从而在长序列上拿到数倍加速。这说明一个更普遍的工程规律：在 Transformer 上，很多性能问题不是算力不够，而是数据搬得太远。

    06、LLM 如何生成一段文本

    6.1 完整流程

    用户输入
   ↓
Tokenize
   ↓
Embedding
   ↓
Transformer（N 层）
   ↓
计算 Logits（整个词表上的分数）
   ↓
Softmax → 概率分布
   ↓
按策略选择 1 个 Token
   ↓
拼回输入，循环

    整个过程叫自回归生成：每次只吐一个 Token，然后把这个 Token 追加到输入末尾，重新跑一遍完整的前向传播，再吐下一个。所谓“流式输出”逐字往外蹦，不是界面特效，而是它真实的计算节奏。

    6.2 Logits 与两个阶段

    Logits 是 Softmax 之前的原始分数，长度等于词表大小（现在常见 10 万到 20 万）。分数的高低只代表相对可能性，没有绝对意义；经过 Softmax 之后才成为概率，且所有概率之和为 1。

    这里有一个对推理性能至关重要的区分：

    • Prefill 阶段：并行处理整段输入 Prompt。所有位置同时算，是计算密集型的，耗时决定了首 Token 延迟（TTFT）。Prompt 越长，首字越慢。
    • Decode 阶段：逐个生成 Token，每步只算一个位置，是显存带宽密集型的，耗时决定了每 Token 输出时间（TPOT）。

    这解释了一组看起来很矛盾的现象：长 Prompt 的首字延迟很高但整体吞吐大；长输出则慢得很均匀，因为瓶颈在把模型权重从显存搬进计算单元，而每次只喂进一个 Token。

    由此也引出了 KV Cache。既然每次生成都要重算整个前文，而前文的 Key 和 Value 并不会因为新 Token 出现而改变，那就把它们的计算结果缓存下来——第 n 步只需要计算新 Token 的 Q、K、V，然后和缓存的 K、V 做注意力。这让生成复杂度从每步 O(n²) 降到 O(n)。代价是显存：KV Cache 的大小随序列长度线性增长，长上下文场景下它经常比模型权重本身还占显存。这正是 MQA / GQA 存在的意义——多个头共享 K/V，直接把 Cache 压缩数倍。

    6.3 从概率分布到实际选出的那个 Token

    拿到概率分布之后，怎么选？这一步完全决定输出的“性格”。

    Greedy（贪心 / argmax）：永远选概率最高的那个。确定、可复现，但在开放生成里容易陷入重复和呆板，因为没有探索。

    Temperature（温度）：先用温度 T 缩放 logits，再 Softmax：

    P_i = softmax(z_i / T)

    理解它只需抓住两点。第一，它不改变概率的排序，只改变概率的集中程度：T < 1 让分布更尖锐（更确定、更保守），T > 1 让分布更平坦（更随机、更跳跃），T → 0 数学上就是 argmax。第二，它不是一个线性的“创造力旋钮”：调高温度同时提高了合理多样性和事实错误的发生率，两者无法分离。

    Top-k：先把候选限定在概率最高的 k 个 Token 里，再按概率采样。

    Top-p（核采样 / nucleus sampling）：取累积概率刚好达到 p 的最小 Token 集合，再在其中采样。它比 Top-k 更自适应——模型很确定时集合自动收窄，模型很犹豫时集合自动放宽。这也是现代 API 里最常见的默认配置。

    另外还有重复惩罚（repetition penalty）、存在惩罚（presence penalty）这类调整项，用来压制复读机式输出。

    6.4 对 Agent 工程的三条直接建议

    1. 结构化输出用低温。 工具调用的参数必须是合法 JSON，采样随机性会直接转化为系统故障率。凡是要求确定性、格式严格、可解析的场景，温度取 0 到 0.2。多方案探索、创意发散这类场景才适合高温。
    2. 同一任务只调一个维度。 同时改温度、Top-p 和惩罚项，会让行为变化无法归因，调试成本远超收益。
    3. 先把 Prompt 前缀稳定下来。 结合 Token 成本一节：稳定的前缀意味着缓存命中，缓存命中意味着同样的准确率下更低的单价。这是性价比最高的一步优化。

    07、回到最初的问题

    7.1 LLM 为什么能理解语言

    回到开头那个问题。答案是：“预测下一个 Token”这个目标函数，是对语言全部规律施加的一次极限压缩。

    要在一个足够大的语料上持续压低困惑度，模型被迫同时学会语法结构、语义搭配、指代关系、常识、世界事实、代码语义，以及一部分可复用的推理模式。它没有被显式教过任何一条语言规则，规则是它在优化目标下自己长出来的副产品。

    但必须把“理解”这个词的分寸说清楚，这里有三层：

    • 它学到的是分布，不是真理。 幻觉、知识截止、置信度不可靠，全部源于此，而不是某个可以修补的缺陷。
    • 它的“理解”是操作性的。 这是学界仍在争论的问题。一派观点认为仅从形式分布中学习无法获得真正的语义，模型不过是“随机鹦鹉”；另一派认为在足够的规模与交互下，形式目标足以诱导出功能性的意义表征。作为工程实践者，务实的立场是：按操作性标准使用它、按统计系统评估它——在足够多的下游任务上表现稳定就是可用的，但这不意味着它拥有可依赖的内在真值。
    • 上下文就是程序。 同一份权重，靠不同的提示词和示例，就能执行翻译、抽取、分类、写代码等无数任务。这种 In-context Learning 能力，是 Agent 能成立的根基。

    7.2 它为什么能当 Agent 的推理核心

    把上面几节串起来看，LLM 恰好具备四个 Agent 需要的性质：

    • 通用接口。 自然语言、代码、结构化数据都被映射进同一个 Token 空间。工具调用的本质，就是把“调用哪个函数、参数是什么”变成一段被约束的 Token 生成——不需要为每个工具写专门的解析器。
    • 推理过程可外显。 因为计算量正比于生成的 Token 数，把思考写进 Token 流就等于买到了额外算力。Chain-of-Thought 和测试时计算把这一点变成了可调用的能力：任务越难，就让它多想一会儿。
    • 无需微调即可适配。 提示词、少样本示例、检索上下文，都是在上下文里编程。这意味着 Agent 的行为可以靠 Prompt 和知识库快速迭代，而不必付出训练成本。
    • 失败的代价可控。 它是概率模型，输出可采样、可重试、可多次投票。工程上可以把不确定性变成冗余计算来消化。

    反过来，也要清楚它天生缺什么。它没有可靠的长期记忆，没有内在目标，没有对自身输出的独立验证能力，也没有对事实的强制约束。Agent 工程的全部内容，本质就是围绕这些缺口做补偿：

    • 用工具补事实获取与真实世界执行；
    • 用检索补长期记忆与知识新鲜度；
    • 用验证循环补自我检查（重试、单元测试、schema 校验、二次审阅）；
    • 用多步编排补长程规划（任务拆分、状态机、显式计划）。

    所以最终的回答可以收得很简洁：

    LLM 不是一颗会思考的大脑，它是一个把“下一步最可能是什么”做到极致的函数。它之所以能理解语言，是因为语言的全部规律都被压缩进了这个目标里；它之所以能成为 Agent 的推理核心，是因为它把一切任务统一成了同一件事——生成 Token。而 Agent 的工程质量，取决于你在它周围补上了多少它天生缺失的东西。
